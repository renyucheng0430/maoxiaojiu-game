【一、原始需求（用户要求，必须遵守）】
依托 E:\猫小九\ 目录里的资料做一个情景互动类游戏，使用 HTML。
- 大型游戏，不要用"巨多小游戏"的风格，参考市面主流同类游戏；画风 3D 动漫风
  （Three.js 立体山谷场景 + 漫画透明立绘人物）。注：需求里曾写"2D"，经用户确认为笔误，实际要 3D。
- 文字资料由音频转录，可能有错别字，一切以漫画图片和音频为准。
- 注意：
  1. 不要乱改人物形象（形象以漫画为准）。
  2. 所有文件都放在 E:\猫小九\Game 目录里，不放工作区。
- 界面要求：
  1. 以猫小九第一人称视角。
  2. 界面右上方有 主线/支线/挑战 任务面板（依据资料取得）。
  3. 界面左侧 5 个按钮：背包、我的、修行、关系、章节。
  4. 人物可走动，用虚拟摇杆操控（也支持 WASD/方向键，E 或点击 NPC 对话）。

【三、关键技术决策与"为什么这么做"】
- 渲染方式：Three.js（WebGL）真 3D——透视相机从斜上方跟随玩家，可拖动屏幕环绕旋转。
  人物用漫画透明 PNG 立绘做成始终面向相机的 Sprite（billboard），
  既保证 3D 空间穿行感，又不乱改人物形象；场景物体为 3D 几何体。
- 关于 file:// 双击打开：Chrome 对 file:// 页面的 WebGL 本地贴图有安全限制
  （图片会污染纹理，texImage2D 报 SecurityError）。解决方案：已把 7 张角色立绘与 6 张背景
  全部转成 base64 data URI，分别内嵌在 assets\data\sprites-data.js 与 backdrops-data.js，
  data URI 不跨域、不污染 WebGL，因此双击 index.html 即可看到真立绘与远景画卷，无需起本地服务。
  仍保留 try/catch 降级：极端情况下自动切 canvas 应急立绘，3D 场景与 UI 始终可玩。
- 背景：六张漫画风山谷画卷（backdrops/*.jpg，已转 base64）作为场景远景背景，随所在区域切换；
  地面为立体草地 + 立体泥土小径（连接家/学堂/练武场/部落广场/林间），散布草丛、小花、石块，
  纹理统一缓存，切换区域不重复加载。
- 人物形象一律使用原透明 PNG 立绘，不做任何外形改动。

【五、可调参数（想改手感时改这里）】
- 3D 相机：js/game.js 里 camH（相机高度，默认24，拖动上下调整）、CAM_DIST（跟随距离）；
        区域/角色世界坐标见 zones 与 npcs 数组。
- 角色大小：buildCharacters() 里 playerSprite / NPC sprite 的 scale。
- 任务初始状态：assets\data\game-data.js 里各 quest 的 status 字段
        （active=进行中 / locked=未开始 / completed=已完成）。
- 任务面板：css\style.css 里 #quest-panel（宽度280px）。
